# Getting started

From zero to your first green run in about five minutes. No Rust toolchain needed — just install and go. You'll install the engine, scaffold a project, and run the starter suite; afterwards every chapter builds on this loop.

<StepBlock step={1} title="Download and install">

<StepDescription>Pick the installer that fits your machine. Every option bundles the engine (`tuilab` + `tuilab-mcp`) — nothing else to download.</StepDescription>

<CodeTabs tabs={[
  {
    label: 'Windows', value: 'windows', content:
    <Snippet label="powershell" code={`pip install tui-lab
tuilab --version`} />,
  },
  {
    label: 'macOS / Linux', value: 'unix', content:
    <Snippet label="bash" code={`pip install tui-lab
tuilab --version`} />,
  },
  {
    label: 'Node.js', value: 'node', content:
    <Snippet label="bash" code={`npx @tui-lab/cli --version`} />,
  },
  {
    label: 'Rust', value: 'rust', content:
    <Snippet label="bash" code={`cargo install tui-lab-cli tui-lab-mcp
tuilab --version`} />,
  },
  {
    label: 'Portable archive', value: 'archive', content:
    <Snippet label="bash" code={`# Download the archive for your OS from GitHub Releases,
# unzip it, and add the folder to your PATH.
tuilab --version`} />,
  },
]} />

<Callout title="Prefer uv?">`uv add tui-lab` works the same as pip, and `uvx tui-lab run …` runs without installing anything.</Callout>

<Callout title="What you get">Every installer bundles both binaries: `tuilab` (the engine + CLI) and
`tuilab-mcp` (the MCP server for AI agents). Check `tuilab-mcp --help` works
too if you plan to connect an agent.</Callout>

</StepBlock>

<StepBlock step={2} title="Scaffold a project" tag="tuilab init">

<StepDescription>Create `tuilab.yaml` plus a starter smoke suite. The config file is
optional — a missing file means defaults — but having one makes the project
self-documenting.</StepDescription>

<Snippet label="bash" code={`tuilab init
# -> tuilab.yaml + tests/smoke.yaml`} />

<Example title="Generated tuilab.yaml" description="Project settings created by init — edit paths, terminal size, and timeouts to taste. Every key is optional.">

<Snippet label="tuilab.yaml" code={`version: "1.0"
tests_dir: tests
snapshots_dir: tests/snapshots
default_terminal: { width: 120, height: 40 }
default_timeout: 10s
parallel: 4
report:
  json: reports/results.json
  junit: reports/junit.xml
  html: reports/index.html
env:
  TERM: xterm-256color
security:
  allow_commands:      # MCP launch allowlist (regexes)
    - "^\\\\./.*"
    - "^cargo run.*"
    - "^python.*"`} />

</Example>

<Callout title="Point smoke at your app">The generated `tests/smoke.yaml` launches a placeholder
`command: "./myapp"`. Edit `command` (and `args`) to your binary, then run.</Callout>

</StepBlock>

<StepBlock step={3} title="Run your first suite" tag="tuilab run">

<StepDescription>Run the starter suite. A green run looks like this:</StepDescription>

<Snippet label="bash" code={`tuilab run tests`} />

<OutputBlock title="expected output">

✓ smoke
2 passed, 0 failed

</OutputBlock>

Each run ends with an exit code: `0` all passed, `1` a test failed, `2` config/schema error, `3` launch/PTY error, `4` timeout with the hung process killed. Results land in `reports/results.json` (plus JUnit/HTML per your config), and every failed run retains a trace archive under `reports/traces/`.

</StepBlock>
